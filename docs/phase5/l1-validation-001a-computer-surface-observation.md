# L1 Validation 001A — Computer Surface Observation

## 1. Status

```
Status: observation recorded / validation note
```

This is not a full test report and not a new architecture spec. It records
what was observed in the first real-path L1 computer surface run.

## 2. Run Context

- L1 real-path `COMPUTER.md` MVP was available in the detached room.
- `--library-path` and `--computer-root` were used together as separate, additive inputs.
- The run involved multiple instances / continuations (approximately 5).
- The observed material from the readable computer surface involved "小杰" (xiaojie) — a character-origin document from an external vault path.

## 3. Main Observation

Computer/source material about 小杰 entered the room through the L1 computer surface.

Across 5 instances:

- **Not every instance read the computer/source material directly.** Some instances picked up the thread from prior room traces rather than from COMPUTER.md.
- **Distributed reading across instances was enough.** The material propagated through the room's own file surface — HELLO.md, emergent files, and accumulated traces carried the thread forward.
- **External material became part of room growth.** The room transformed outside character-origin material into narrative and conceptual growth rather than summarizing source files.
- **No evidence of source-analysis collapse.** The room did not turn into a report about 小杰.
- **No evidence of apparatus/path fixation.** The agent did not get stuck explaining the computer, the path names, or the framework.

Key finding:

> L1 is an environment condition, not a mandatory per-instance checklist. The computer surface is available. Some instances use it. Others continue from what prior instances left. Both are valid.

## 5. Why This Matters

L1 exists to keep the room open to outside novelty, traces, resistance, and
memory — preventing the closed self-referential loop that source-conditioned
rooms can enter after saturation.

The important behavior is not that every instance reads `COMPUTER.md`. It is
that the computer surface can become a **live outside input** that some
instances use and that the room as a whole can absorb, transform, and grow from.

In this run, the computer worked exactly that way: it seeded external material
that the room metabolized across multiple instances without collapsing into
source analysis or apparatus commentary.

## 6. Non-Goals

- This does not require every future instance to read the computer.
- This does not require mandatory computer-use logging.
- This does not add OS sandboxing, watcher, daemon, or heavy permission machinery.
- This does not redefine `--library-path`.
- This does not replace A2 source-as-soil.
- This does not create a new validation framework or required observation protocol.
